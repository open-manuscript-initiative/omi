# Open Manuscript Studio — Τρέχουσα κατάσταση υλοποίησης

## Στιγμιότυπο

| Πεδίο | Τιμή |
|---|---|
| Κατάσταση | **Beta** |
| Ημερομηνία δημιουργίας στιγμιότυπου | **5 Σεπτεμβρίου 2026** |
| Τρέχουσα σειρά εκδόσεων | `0.1.0-beta.3` |
| Υλοποίηση αναφοράς | Open Manuscript Studio |
| Αποθήκη πηγαίου κώδικα | `open-manuscript-initiative/open-manuscript-studio` |
| Στόχος ιστού | Σύγχρονα προγράμματα περιήγησης |
| Στόχοι για επιτραπέζιους υπολογιστές | Windows x64, Linux x64, macOS Intel, macOS Apple Silicon |
| Στόχοι για κινητά | Δημόσιο APK γενικής χρήσης για Android· επικυρωμένος εγγενής στόχος προσομοιωτή για iOS/iPadOS, με τη διανομή μέσω TestFlight/App Store να εκκρεμεί έως ότου ολοκληρωθεί η υπογραφή από την Apple Developer |
| Ανάπτυξη ιστού | `studio.openmanuscript.org` |

Η τρέχουσα έκδοση beta του Studio είναι **`0.1.0-beta.3`**. Ο όρος «beta» σημαίνει ότι έχουν υλοποιηθεί οι βασικές ροές εργασίας δημιουργίας περιεχομένου, εισαγωγής/εξαγωγής, ελέγχου ταυτότητας, εγγενούς πελάτη και αναθεώρησης μέσω των διευθύνσεων OJS/OMP, ενώ το έργο έχει περάσει από το στάδιο της αρχικής ανάπτυξης λειτουργιών στο στάδιο της διαλειτουργικότητας, των δοκιμών παλινδρόμησης, της αποκατάστασης και της τελικής προετοιμασίας για την κυκλοφορία. **Δεν** σημαίνει όμως ότι κάθε προαιρετική ενσωμάτωση ή κανάλι διανομής έχει ολοκληρωθεί για την παραγωγή.

Αυτή η σελίδα περιγράφει τις **υλοποιημένες δυνατότητες του προϊόντος** και όχι τη συμμόρφωση με τις προδιαγραφές τουOMI. Η ωριμότητα των επίσημων προδιαγραφών και τα αποδεικτικά στοιχεία συμμόρφωσης παρακολουθούνται ξεχωριστά στο [OMI Implementation Status Matrix](./implementation-status-matrix.md).

## Λεξιλόγιο κατάστασης

- **Λειτουργικό** — έχει ενσωματωθεί στην τρέχουσα σειρά ανάπτυξης του Studio και είναι διαθέσιμο όταν πληρούνται οι συνήθεις προϋποθέσεις εκτέλεσης.
- **Εξαρτάται από τη διαμόρφωση** — έχει υλοποιηθεί, αλλά απαιτεί διαπιστευτήρια διακομιστή ειδικά για την εγκατάσταση, εγγραφή στο OAuth/OIDC, παράδοση αλληλογραφίας, εξωτερική υπηρεσία, μετεγκατάσταση βάσης δεδομένων ή σύνδεση με σύστημα δημοσίευσης.
- **Επαληθευμένος εγγενής προορισμός** — υπάρχει υλοποίηση και επαλήθευση της κατασκευής CI/εγγενούς έκδοσης, αλλά η δημόσια διανομή εξακολουθεί να εξαρτάται από την υπογραφή/προετοιμασία της πλατφόρμας.
- **Βάση** — Υπάρχει υποστήριξη για την αρχιτεκτονική, το μητρώο, το περιβάλλον χρήστη ή τη διαμόρφωση, αλλά η πλήρης υπηρεσία για τον τελικό χρήστη δεν έχει ακόμη χαρακτηριστεί ως λειτουργική.

Οι οθόνες Studio/Account σε πλήρες παράθυρο και η επιλογή εμφάνισης/απόκρυψης της δομής εγγράφου τύπου Word διευκολύνουν την πλοήγηση σε εκτενή κείμενα, ενώ η έκδοση για κινητά διατηρεί τη συμπαγή δομή της ροής εργασίας. |

| Στοιχεία ελέγχου μορφοποίησης εμπλουτισμένου κειμένου | **Λειτουργικό** | Η συμπυκνωμένη ενσωματωμένη μορφοποίηση παραμένει διαθέσιμη κοντά στην επιλογή· το αναπτυγμένο μενού για επιτραπέζιους υπολογιστές είναι αγκυρωμένο και προσαρμόζεται στο παράθυρο προβολής, ενώ η ενσωματωμένη γλώσσα επιλέγεται από τις διαμορφωμένες γλώσσες του χειρογράφου και όχι από ελεύθερο κείμενο. Η αυτόματη πλωτή μορφοποίηση μπορεί να απενεργοποιηθεί στις ρυθμίσεις του επεξεργαστή. | Δομημένη αναζήτηση και αντικατάσταση | **Λειτουργικό** | Επικάλυψη αναζήτησης/αντικατάστασης, πεδία εφαρμογής και πλοήγηση στα αποτελέσματα με προσαρμοσμένη πρόσβαση που χρησιμοποιείται τόσο στις διατάξεις για επιτραπέζιους υπολογιστές όσο και για κινητές συσκευές. |
| Πολύγλωσσο περιβάλλον χρήστη | **Σε λειτουργία** | Υποστηρίζονται 24 ευρωπαϊκές γλώσσες για το περιβάλλον χρήστη με κοινή επιλογή γλώσσας. Οι προτιμήσεις γλώσσας για το περιβάλλον χρήστη, το χειρόγραφο και τα μεταδεδομένα διαχειρίζονται σε μία συμπαγή και προσαρμοστική επιφάνεια ρυθμίσεων. |
| Προτιμήσεις ζώνης ώρας | **Λειτουργικό** | Τυπική επιλογή ζώνης ώρας IANA με τις τρέχουσες αποκλίσεις από το UTC και αυτόματη ρύθμιση της προεπιλεγμένης ζώνης ώρας του συστήματος. |
| Πολύγλωσση βοήθεια | **Λειτουργική** | Ενσωματωμένη τοπικοποιημένη κάλυψη βοήθειας σε όλες τις υποστηριζόμενες γλώσσες του περιβάλλοντος χρήστη του Studio· Οι οθόνες βοήθειας εμφανίζουν την τρέχουσα έκδοση της έκδοσης. |
| Λογαριασμοί και πιστοποίηση | **Λειτουργικό** | Η εγγραφή/σύνδεση με υποστήριξη από διακομιστή, η αποσύνδεση και η πιστοποιημένη πρόσβαση στο API λειτουργούν σε διαδικτυακούς και εγγενείς πελάτες. Ο ίδιος κεντρικός λογαριασμός μπορεί να χρησιμοποιηθεί σε πελάτες Windows, Android, iOS/iPadOS και προγραμμάτων περιήγησης. Οι εγγενείς πελάτες χρησιμοποιούν μεταφορά τύπου «bearer-session» συμβατή με τις πηγές εφαρμογών Tauri. |
| Ανάκτηση κωδικού πρόσβασης | **Εξαρτάται από τη διαμόρφωση** | Η διαδικασία «Ξεχάσατε τον κωδικό πρόσβασης/Επαναφορά» χρησιμοποιεί διακριτικά επαναφοράς μίας χρήσης με ημερομηνία λήξης, τα οποία αποθηκεύονται μόνο ως κατακερματισμοί, γενικές απαντήσεις σχετικά με την ύπαρξη λογαριασμού και ανάκληση όλων των συνεδριών μετά από επιτυχή αλλαγή κωδικού πρόσβασης. Απαιτείται η σωστή λειτουργία της υπηρεσίας αποστολής email του διακομιστή. |
| Ομοσπονδιακή σύνδεση | **Εξαρτάται από τη διαμόρφωση** | Οι πάροχοι OIDC της Google, της Microsoft και οι διαμορφώσιμοι γενικοί/ιδρυματικοί πάροχοι χρησιμοποιούν κωδικό εξουσιοδότησης + PKCE, επικύρωση κατάστασης/nonce, επικύρωση discovery/JWKS και ρητή σύνδεση λογαριασμού. Οι υπάρχοντες λογαριασμοί δεν συνδέονται ποτέ αυτόματα μόνο με βάση το ηλεκτρονικό ταχυδρομείο. |
| Συνδεδεμένες ταυτότητες σύνδεσης | **Πάροχοι που εξαρτώνται από τη λειτουργία ή τη διαμόρφωση** | Οι ρυθμίσεις λογαριασμού εμφανίζουν τον κωδικό πρόσβασης και τις συνδεδεμένες ταυτότητες ORCID/OIDC, επιτρέπουν τη σύνδεση ή την αποσύνδεση των διαμορφωμένων παρόχων και αποτρέπουν τη διαγραφή της τελευταίας λειτουργικής μεθόδου σύνδεσης. |
| Διεπαφή λογαριασμού/προφίλ | **Λειτουργικό** | Η επεξεργασία του προσωπικού προφίλ, η οποία υποστηρίζεται από κοινόχρηστο διακομιστή, είναι διαθέσιμη σε όλες τις διατάξεις για επιτραπέζιους υπολογιστές και κινητά, ενώ η ταυτότητα του λογαριασμού διαχωρίζεται από τα μεταδεδομένα των συντελεστών των χειρογράφων και την ιδιότητα μέλους συγκεκριμένου οργανισμού. |
| Προφίλ ιδρυμάτων | **Λειτουργικά** | Ένας λογαριασμός στο Studio μπορεί να περιλαμβάνει πολλαπλές ιδιότητες μέλους σε ιδρύματα με μία προεπιλεγμένη ιδιότητα. Τα κοινά δεδομένα για το όνομα του ιδρύματος και τη διεύθυνσηROR διαχωρίζονται από τα στοιχεία που αφορούν συγκεκριμένα την ιδιότητα μέλους, όπως το τμήμα, η θέση, το ιδρυματικό e-mail, η συνδεδεμένη ταυτότητα και ο ρόλος. |
| Ρόλοι διαχειριστών ιδρύματος | **Εξαρτάται από τη διαμόρφωση** | Οι ρόλοι `MEMBER`, `ADMIN` και `OWNER` του ιδρύματος έχουν ισχύ διακομιστή. Οι εγκαταστάσεις σε επίπεδο ιδρύματος παρέχουν ειδική σύνδεση διαχειριστή και διαχείριση μελών που προστατεύεται από ρόλους, με προστασία του τελευταίου ιδιοκτήτη. |
| Κεντρική διαχείριση OMI | **Εξαρτάται από τη διαμόρφωση** | Ένα ξεχωριστό κεντρικό επίπεδο προνομίων `ADMIN`/`OWNER` μπορεί να διαχειρίζεται ιδρύματα, διαχειριστές ιδρυμάτων, διαπιστευτήρια API και συμβάντα ελέγχου της διαχείρισης, χωρίς να αποκτά πρόσβαση σε χειρόγραφα ή συντακτικό περιεχόμενο. |
| Διαχειριστής ιδρύματος API | **Εξαρτάται από τη διαμόρφωση** | Τα διαπιστευτήρια συσκευής που συνδέονται με το ίδρυμα χρησιμοποιούν εμφάνιση ακατέργαστου διακριτικού μίας χρήσης, αποθήκευση με κατακερματισμό, λήξη/ανάκληση και ρητά πεδία εφαρμογής (`institution:read`, `members:read`, `members:write`, πεδία εφαρμογής που προορίζονται για ενσωμάτωση). Τα διαπιστευτήρια συσκευής δεν μπορούν να αλλάξουν τους ρόλους των κατόχων. |
| Μοντέλο ταυτότητας συνεισφερόντων | **Λειτουργικό** | Οι συνεισφέροντες, οι ρόλοι, οι συνδέσεις, οι δηλώσεις ταυτότητας και οι ροές εργασίας προφίλ συγγραφέων παρουσιάζονται ξεχωριστά από την ταυτότητα του λογαριασμού. |
|  ΠιστοποίησηORCID | **Εξαρτάται από τη διαμόρφωση** |  ORCID  OAuth  Έχει υλοποιηθεί η υποδομή σύνδεσης και σύνδεσης μέσω OIDC. Τα σύνολα διαπιστευτηρίων για την προσωπική και την οργανωτική ανάπτυξη είναι διαχωρισμένα, ενώ το ενεργό περιβάλλον Sandbox/Production είναι ορατό στο περιβάλλον εργασίας χρήστη του Studio. |
| Φορητές υπογραφές συγγραφέα με δέσμευση σε συγκεκριμένο περιβάλλον (ORCID) | **Εξαρτάται από τη διαμόρφωση** | Έχουν υλοποιηθεί αμετάβλητα στιγμιότυπα αναθεώρησης που έχουν καταχωρηθεί στον διακομιστή, δέσμευση συγγραφέα με δέσμευση σε συγκεκριμένο περιβάλλον (ORCID), υπογραφή με δέσμευση σε συγκεκριμένο περιβάλλον (WebAuthn), κρυπτογραφημένα κλειδιά εκδότη εγκατάστασης και φορητά αποδεικτικά στοιχεία επαλήθευσης εκτός σύνδεσης. |
| Διπλά τυφλή αξιολόγηση από ομότιμους | **Σε λειτουργία** | Προβολή ανώνυμων αξιολογητών, ανάθεση αξιολογήσεων, χώρος εργασίας αξιολογητών, σχόλια και διατήρηση των αξιολογήσεων. Τα δικαιώματα πρόσβασης των αξιολογητών περιορίζονται στο πλαίσιο του ρόλου τους, ώστε να τηρείται η αρχή του ελάχιστου προνομίου. |
| Πίνακας ελέγχου συντακτικής αξιολόγησης | **Λειτουργικό** | Επισκόπηση για τους συντάκτες και πύλη αξιολόγησης με διαχωρισμό ρόλων για τις εργασίες ομότιμης αξιολόγησης που τους έχουν ανατεθεί. |
| Αμφίδρομη επαναγραφή αξιολόγησης μέσω του OJS | **Εξαρτάται από τη διαμόρφωση / έχει επικυρωθεί** | Η υπογεγραμμένη επαναγραφή αξιολόγησης επιστρέφει τα υποβληθέντα δεδομένα αξιολόγησης στο OJS. Τα πεδία εκκίνησης των αξιολογητών βασίζονται στην αρχή των ελάχιστων προνομίων, ενώ το πρωτόκολλο αξιολόγησης δύο γύρων OJS έχει τεκμηριωθεί και έχει εφαρμοστεί στην γραμμή ενσωμάτωσης OJS 3.5. |
| Εγγενείς φόρμες αξιολόγησης του OJS | **Εξαρτάται από τη διαμόρφωση / επικυρωμένες** | Οι ορισμοί των φορμών αξιολόγησης του OJS μπορούν να εισαχθούν στον χώρο εργασίας του αξιολογητή, να απεικονιστούν ως στοιχεία ελέγχου του Studio, να μεταφραστούν με ασφάλεια και να αποσταλούν ξανά στο OJS μαζί με την υποβληθείσα αξιολόγηση. Η διαχείριση από τον διακομιστή διατηρεί την σήμανση του παρόχου αδιαφανή, ενώ η απεικόνιση από τον πελάτη εξάγει το κείμενο με ασφάλεια. |
| Εξωτερικές αναθέσεις αξιολόγησης /OJS | **Εξαρτάται από τη διαμόρφωση** | OJS- οι συνδεδεμένες ροές εργασίας συγγραφέων, εκδοτών και κριτών, καθώς και το πλαίσιο των εξωτερικών αναθέσεων, υλοποιούνται όταν έχει διαμορφωθεί η ενσωμάτωση του OJS. |
| OJS εκκίνηση/εισαγωγή χειρογράφου | **Εξαρτάται από τη διαμόρφωση** | Υπογεγραμμένες δηλώσεις εκκίνησης, ανάκτηση χειρογράφου/αρχείου και δομημένη εισαγωγή μεταδεδομένων και περιεχομένου χειρογράφου από το OJS. |
| ΔιαλειτουργικότηταOJS3.5 | **Επαληθευμένη γραμμή ενσωμάτωσης** | Η συμβατότητα PKP/OJS3.5 τεκμηριώνεται και δοκιμάζεται σε εγγενείς ροές εργασίας από άκρο σε άκρο για συγγραφείς, συντάκτες και διπλά ανώνυμους κριτές, συμπεριλαμβανομένων των εκχωρημένων αρχείων, των εντύπων αξιολόγησης, των διορθώσεων, των ξεχωριστών σχολίων και της υπογεγραμμένης επαναφοράς. Η παλινδρόμηση μεταξύ εκδόσεων παραμένει συνεχιζόμενη εργασία κάθε έκδοσης. |
| Παρουσίαση και αξιολόγηση χειρογράφων/μελετών στο OMP | **Εξαρτώμενο από τη διαμόρφωση / επικυρωμένο** | Οι υπογεγραμμένες δηλώσεις παρουσίασης αντιστοιχίζουν μονογραφίες και δημοσιεύσεις στο Studio, ενώ η πρόσβαση των κριτών περιορίζεται στη συγκεκριμένη μελέτη που τους έχει ανατεθεί. Οι ροές εργασιών για συγγραφείς, επιμελητές και κριτές με διπλή ανωνυμία καλύπτουν τα αρχεία που τους έχουν ανατεθεί, τα έντυπα αξιολόγησης, τις διορθώσεις, τα ξεχωριστά σχόλια και την υπογεγραμμένη αποστολή των διορθώσεων. |
| Διαλειτουργικότητα τουOMP 3.5 | **Επαληθευμένη γραμμή ενσωμάτωσης** | Το plugin «OMP» που μπορεί να αναπτυχθεί και η ενσωμάτωση στο Studio έχουν δοκιμαστεί από άκρο σε άκρο σε σχέση με το OMP 3.5. Οι ευρύτερες δοκιμές παλινδρόμησης μεταξύ εκδόσεων και η ενίσχυση της σταθερότητας σε περιβάλλον παραγωγής παραμένουν σε εξέλιξη ως μέρος των εργασιών της έκδοσης. |
| Εισαγωγή δομημένου περιεχομένουDOCX| **Λειτουργικό** | Υποστηρίζονται οι επικεφαλίδες, η ενσωματωμένη σημασιολογία, η κληρονομικότητα λιστών, οι υποσημειώσεις/τελικές σημειώσεις, οι παραπομπές, οι δομημένοι πίνακες και τα πεδία σημασιολογικού ευρετηρίου. Οι μεγάλες εισαγωγές χρησιμοποιούν αναβαλλόμενη ενσωμάτωση στον επεξεργαστή, ενώ τα εισαγόμενα αρχεία τύπου «DOCX» ανοίγουν απευθείας ως έγγραφα τύπου «OMI». |
| Δυναμικοί δείκτες και λίστες | **Λειτουργικό** | Τα πεδία ευρετηρίου που εισάγονται από το Word αναπαρίστανται σημασιολογικά και όχι ως παρωχημένο κείμενο με αριθμούς σελίδων. ## Αρχιτεκτονική πολλαπλών πλατφορμών

Το Studio διαθέτει μια συγκεκριμένη αρχιτεκτονική κοινών πελατών, αντί για ξεχωριστές σειρές προϊόντων για το διαδίκτυο και για εγγενείς εφαρμογές. React/TypeScript: το μοντέλο χειρογράφων OMI, η συμπεριφορά του επεξεργαστή, οι ροές πιστοποίησης, η αξιολόγηση από ομοτίμους, οι ενσωματώσεις και η λογική εισαγωγής/εξαγωγής είναι κοινές. Το Tauri 2 παρέχει δυνατότητες εγγενούς συσκευασίας και πλατφόρμας για πελάτες επιτραπέζιων υπολογιστών και κινητών συσκευών.

Η προσαρμοστική διεπαφή χρήστη διαφέρει σκόπιμα ανάλογα με τον τύπο συσκευής: οι επιτραπέζιοι υπολογιστές μπορούν να εμφανίζουν καρτέλες πολλαπλών εγγράφων, μια μόνιμη δομή εγγράφου και επεξεργασία σε πολλαπλά πλαίσια, ενώ οι κινητές συσκευές χρησιμοποιούν συμπαγή πλοήγηση, συρτάρια, στοιχεία ελέγχου προσαρμοσμένα στην αφή και εργαλεία επιλογής αρχείων εγγενή στην πλατφόρμα. Πρόκειται για διαφορά στην παρουσίαση και όχι για ξεχωριστό μοντέλο χειρογράφου.

Ο στόχος iOS/iPadOS χρησιμοποιεί τον ίδιο κοινό πελάτη για κινητά. Οι εργασίες που αφορούν ειδικά την Apple περιορίζονται στη συσκευασία εγγενών εφαρμογών, στην πρόσβαση σε έγγραφα μέσω των εφαρμογών «Αρχεία» και «UIDocumentPicker», στα μεταδεδομένα της εφαρμογής, στην υπογραφή/προετοιμασία και στη συσχέτιση με Universal Links.

## Όρια αρχιτεκτονικής

### Προτεραιότητα στην τοπική κυριότητα των χειρογράφων

Η εγγενής εφαρμογή μπορεί να αποθηκεύει τα χειρόγραφα σε χώρο αποθήκευσης που επιλέγει ο συγγραφέας. Ένα χειρόγραφο δεν χρειάζεται να μετατραπεί σε κατάσταση αποκλειστικής ιδιοκτησίας του διακομιστή απλώς και μόνο επειδή έχουν ενεργοποιηθεί λειτουργίες ταυτότητας, συνεργασίας ή ενσωματώσεων που υποστηρίζονται από τον διακομιστή.

Οι εγκατεστημένοι πελάτες του Studio διακρίνουν μια αξιόπιστη προσωπική συσκευή από μια κοινόχρηστη/ξένη συσκευή. Σε μια προσωπική συσκευή, μπορούν να διατηρηθούν οι συνήθεις διαδρομές εργασίας στον τοπικό χώρο αποθήκευσης ή στο σύστημα. Σε μια κοινόχρηστη συσκευή, το Studio προτιμά συνδέσεις στο cloud που περιορίζονται στο προφίλ και δεν διατηρεί την επιλεγμένη τοπική διαδρομή· οι φορητές/αφαιρούμενες συσκευές αποθήκευσης μίας χρήσης παραμένουν διαθέσιμες.

### Ταυτότητα και υπηρεσίες που υποστηρίζονται από διακομιστή

Οι λογαριασμοί, η ανάκτηση κωδικού πρόσβασης, οι συνδεδεμένες ταυτότητες, η ομοσπονδιακή σύνδεση, η συνεργασία, η αξιολόγηση από ομοτίμους, οι άμεσες συνδέσεις με το cloud, η διαχείριση ιδρυμάτων και οι ενσωματώσεις συστημάτων δημοσίευσης χρησιμοποιούν τις υπηρεσίες που υποστηρίζονται από το Studio API και το PostgreSQL. Η ταυτότητα πιστοποίησης διατηρείται ξεχωριστή από την ταυτότητα του επιστημονικού συνεισφέροντα και από την ιδιότητα μέλους του ιδρύματος. Αυτές οι λειτουργίες εξαρτώνται από τη σωστή διαμόρφωση και μετεγκατάσταση της εγκατάστασης.

### Όρια διοικητικής δομής

Η ιδιότητα μέλους ενός ιδρύματος (`MEMBER` / `ADMIN` / `OWNER`) και η κεντρική διοίκηση του OMI (`ADMIN` / `OWNER`) αποτελούν ξεχωριστά επίπεδα εξουσιοδότησης. Κανένα από τα δύο δεν παρέχει από μόνο του πρόσβαση σε χειρόγραφα, κριτικές ή συντακτικό περιεχόμενο. Τα διαπιστευτήρια του API ενός ιδρύματος συνδέονται με ένα συγκεκριμένο ίδρυμα και συγκεκριμένα πεδία εφαρμογής, και δεν μπορούν να τροποποιήσουν τους ρόλους των κατόχων.

Δείτε τη διεύθυνση [Institutional and Central Administration](../integrations/institutional-administration.md).

### Εξωτερικές ενσωματώσεις

OMI διαχωρίζει τη σημασιολογία του χειρογράφου από την πιστοποίηση και τη μεταφορά που εξαρτώνται από τον συγκεκριμένο πάροχο. OJS, OMP, αποθήκευση στο cloud, ORCID, πάροχοι ταυτότητας OIDC, υπηρεσίες μετάφρασης και πράκτορες τεχνητής νοημοσύνης συνδέονται επομένως μέσω επιπέδων ενσωμάτωσης, αντί να αποτελούν μέρος του βασικού μοντέλου εγγράφου.

### Αρχή συστήματος έκδοσης

Όσον αφορά τις συνδεδεμένες ροές εργασίας των OJS και OMP, το σύστημα δημοσίευσης εξακολουθεί να αποτελεί την επίσημη πηγή αναφοράς όσον αφορά την κατάσταση της ροής εργασίας υποβολής, τις αναθέσεις, τους γύρους αξιολόγησης και τις συντακτικές αποφάσεις. Το Studio λειτουργεί ως ο δομημένος χώρος εργασίας για τη σύνταξη και την αναθεώρηση και ανταλλάσσει πληροφορίες μέσω καθορισμένων τελικών σημείων της εφαρμογής, αντί για άμεση σύνδεση με τη βάση δεδομένων.

Οι τρέχουσες ενσωματώσεις OJS και OMP είναι αμφίδρομες όσον αφορά τις εργασίες αξιολόγησης: το Studio μπορεί να αξιοποιεί το πλαίσιο εκκίνησης που καθορίζεται από τον ρόλο, τα αρχεία που έχουν ανατεθεί και τους εγγενείς ορισμούς των εντύπων αξιολόγησης, ενώ μπορεί να επιστρέφει υπογεγραμμένες υποβολές αξιολόγησης, διορθώσεις και ξεχωριστά σχόλια συγγραφέα/επιμελητή μέσω του τελικού σημείου ενσωμάτωσης. Επιπλέον, το OMP διατηρεί την αντιστοίχιση μονογραφίας/δημοσίευσης/μελέτης και περιορίζει τους αξιολογητές στη μελέτη που τους έχει ανατεθεί. Αυτό δεν μεταφέρει την εξουσία της ροής εργασίας από το OJS ή το OMP στο Studio.

## Κυκλοφορία και διανομή

`0.1.0-beta.3` αποτελεί την τρέχουσα σειρά εκδόσεων beta του Studio. Το GitHub Actions δημιουργεί αρχεία έκδοσης από τον κοινόχρηστο πηγαίο κώδικα για Windows, Linux, macOS και Android. Η δημόσια σελίδα λήψης του Studio παρέχει πρόσβαση μέσω του προγράμματος περιήγησης και παρουσιάζει τα διαθέσιμα εγγενή πακέτα, συμπεριλαμβανομένου του καθολικού APK για Android.

Το iOS/iPadOS διαθέτει προς το παρόν μια επιτυχημένη έκδοση για τον προσομοιωτή στο πλαίσιο της συνεχούς ενσωμάτωσης (CI), αντί για ένα δημόσιο αρχείο IPA. Η διαδικασία διανομής της Apple είναι έτοιμη, αλλά έχει διαχωριστεί σκόπιμα από την επικύρωση μέσω προσομοιωτή: οι εκδόσεις για το κοινό ή για συσκευές απαιτούν το πραγματικό αναγνωριστικό της ομάδας ανάπτυξης της Apple, το πιστοποιητικό διανομής, το προφίλ παροχής και την τελική διαμόρφωση του «`apple-app-site-association`», προτού καταστεί δυνατή η δημοσίευση στο TestFlight ή στο App Store.

Δείτε το [Open Manuscript Studio on iOS and iPadOS](../foundations/ios-ipados-studio.md).

## Εστίαση στην επικύρωση της έκδοσης beta

Η σειρά beta μετατοπίζει το κριτήριο έγκρισης από το «έχει υλοποιηθεί η κύρια ροή εργασίας;» στο «παραμένει αξιόπιστη σε πραγματικά έγγραφα, πλατφόρμες, ρόλους και συνθήκες σφάλματος;». Οι τρέχουσες προτεραιότητες επικύρωσης είναι:

1. δημιουργία, άνοιγμα, επεξεργασία, αποθήκευση, ρητό κλείσιμο, επαναφορά περιόδου λειτουργίας και επαναλειτουργία χειρογράφου χωρίς απώλεια δεδομένων·
2. μεγάλες και δομικά σύνθετες εισαγωγές DOCX, συμπεριλαμβανομένων σημειώσεων, πινάκων, λιστών, πεδίων και δυναμικών ευρετηρίων·
3. αντιπροσωπευτικές δομημένες διαδρομές εξαγωγής σε διαδικτυακούς και εγγενείς πελάτες·
4. OJS καθώς και OMP ροές εργασίας για την ανταλλαγή χειρογράφων και ροές εργασίας προσαρμοσμένες στους ρόλους συγγραφέα/εκδότη/κριτή, συμπεριλαμβανομένου του καθορισμού του πεδίου εφαρμογής των αρχείων που έχουν ανατεθεί, της αξιολόγησης σε πολλαπλούς γύρους, των ενσωματωμένων εντύπων αξιολόγησης και της υπογεγραμμένης επιστροφής των αρχείων·
5. διπλά τυφλή αξιολόγηση από ομότιμους χωρίς διαρροή ταυτότητας και με πεδία ενσωμάτωσης ελάχιστων δικαιωμάτων·
6. Android Documents/Συμπεριφορά του κύκλου ζωής του SAF και προσαρμοστική πλοήγηση σε κινητές συσκευές·
7. Συμπεριφορά των iOS/iPadOS Files/UIDocumentPicker μόλις καταστεί διαθέσιμη η δοκιμή σε φυσικές συσκευές με υπογραφή·
8. ίδρυμα/κεντρική διοίκηση, χωρίς διαρροή προνομίων στο περιεχόμενο του χειρογράφου·
9. εύκολη στη χρήση διαδικασία αποκατάστασης για τον χρήστη σε περίπτωση σφαλμάτων που αφορούν το δίκτυο, την πιστοποίηση, τη μετεγκατάσταση, την εισαγωγή/εξαγωγή και την ενσωμάτωση.

Οι ενσωματώσεις που εξαρτώνται από τη διαμόρφωση δεν χρειάζεται να είναι διαθέσιμες σε όλους για τη σειρά beta, υπό την προϋπόθεση ότι η ωριμότητά τους προσδιορίζεται σαφώς και ότι δεν θέτουν σε κίνδυνο τις σταθερές βασικές ροές εργασίας.

## Υπόλοιπες εργασίες σταθεροποίησης της έκδοσης beta

- να ολοκληρωθούν οι έλεγχοι παλινδρόμησης για τα Windows και το Android, ιδίως όσον αφορά τη συμπεριφορά των εγγενών λειτουργιών ανοίγματος/κλεισίματος/αποθήκευσης εγγράφων και επαναφοράς συνεδρίας·
- να συνεχίσουμε τις δοκιμές αντοχής σε μεγάλα και δομικά ασυνήθιστα αρχεία DOCX και να βελτιώσουμε την ομαλή αποκατάσταση για δομές του Word που δεν υποστηρίζονται·
- επαναφορά κωδικού πρόσβασης, σύνδεση/αποσύνδεση OIDC και συμπεριφορά της συνεδρίας σε διάφορες συσκευές, με βάση ρυθμίσεις ηλεκτρονικού ταχυδρομείου και παρόχου που προσομοιάζουν τις συνθήκες παραγωγής·
- να εκτελέσει δοκιμές παλινδρόμησης μετεγκατάστασης και εξουσιοδότησης για την ιδιότητα μέλους του ιδρύματος, την κεντρική διοίκηση και τα διαπιστευτήρια του διαχειριστή του ιδρύματος API·
- συνέχεια OJS 3.5: αξιολόγηση πολλαπλών κύκλων και δοκιμές διαλειτουργικότητας μεταξύ εκδόσεων·
- συνέχεια OMP 3.5 διαλειτουργικότητα μεταξύ εκδόσεων, ενίσχυση της ασφάλειας κατά την ανάπτυξη και την αποκατάσταση·
- ενίσχυση των διαδικασιών αποκατάστασης σε περίπτωση διακοπής των λειτουργιών δικτύου, cloud και συγχρονισμού·
- αντικατάσταση των υπόλοιπων επιφανειών τεχνικών/ακατέργαστων σφαλμάτων με μηνύματα προς τους χρήστες που παρέχουν λύσεις·
- να ενσωματώσει τη λειτουργία υπογραφής κώδικα παραγωγής των Windows, εφόσον/όταν γίνει αποδεκτή η εφαρμογή SignPath Foundation·
- συνέχιση των εργασιών υπογραφής/επικύρωσης στο macOS·
- να ρυθμίσετε την υπογραφή/παροχή δικαιωμάτων από την Apple Developer, τη συσχέτιση του Universal Link στην παραγωγή και την επικύρωση μέσω TestFlight/συσκευής πριν προχωρήσετε στη δημόσια διανομή για iOS/iPadOS·
- να συνεχίσουμε το έργο ανάπτυξης μιας διανομής Android προσανατολισμένης στα καταστήματα·
- να αναπτύξουν σειρές δοκιμών συμμόρφωσης που να αντιστοιχούν άμεσα τη συμπεριφορά της υλοποίησης στις κανονιστικές απαιτήσεις του προτύπου OMI·
- να θεσπιστούν εγγυήσεις συμβατότητας σε επίπεδο έκδοσης για τους υποστηριζόμενους προορισμούς εισαγωγής/εξαγωγής.

Η παρουσία μιας λειτουργίας σε αυτό το στιγμιότυπο υλοποίησης δεν πρέπει να ερμηνεύεται ως επίσημη συμμόρφωση με μια προδιαγραφή του Οργανισμού Προτύπων Ανοιχτού Λογισμικού (OMI), εκτός εάν δημοσιευθούν ξεχωριστά η αντίστοιχη κατηγορία συμμόρφωσης και τα σχετικά αποδεικτικά στοιχεία.
