# OMI Υποδομή cloud και ομοσπονδιακή υποδομή

OMI Μπορεί επί του παρόντος να αναπτυχθεί σε συμβατική υποδομή διακομιστών, συμπεριλαμβανομένης της φιλοξενούμενης υπηρεσίας Open Manuscript Studio. Ο μακροπρόθεσμος χάρτης πορείας για την υποδομή αποσκοπεί στο να καταστεί το επίπεδο των υπηρεσιών οριζόντια επεκτάσιμο, διατηρώντας παράλληλα μια αρχή που είναι κεντρικής σημασίας για το OMI: **ένα χειρόγραφο δεν πρέπει ποτέ να εξαρτάται αποκλειστικά από μία φιλοξενούμενη υπηρεσία**.

OMI Συνεπώς, το «Cloud» θεωρείται ως ένα **προαιρετικό επίπεδο υπηρεσιών που διαχειρίζεται και μπορεί να ενταχθεί σε ομοσπονδία**, και όχι ως υποκατάστατο των τοπικών εγγράφων τύπου «`.omi`» ή του χώρου αποθήκευσης που ελέγχεται από το ίδρυμα.

## Στόχοι

Η προτεινόμενη αρχιτεκτονική cloud θα πρέπει να επιτρέπει:

- να συσχετίζει έγγραφα και χώρους εργασίας με λογαριασμούς χρηστών σε προγράμματα περιήγησης, επιτραπέζιους υπολογιστές, συσκευές Android και iOS/iPadOS·
- συγχρονισμός χειρογράφων, εκδόσεων, στοιχείων περιουσίας, δικαιωμάτων πρόσβασης και κατάστασης συνεργασίας σε όλες τις συσκευές·
- υποστηρίζει χώρους εργασίας ατόμων, ερευνητικών ομάδων, εκδοτικών οίκων και ιδρυμάτων·
- να εκτελούν εργασίες εισαγωγής, μετατροπής, επικύρωσης και εξαγωγής που απαιτούν μεγάλη υπολογιστική ισχύ, ανεξάρτητα από το διαδραστικό περιβάλλον εργασίας «API»·
- να καθορίζονται ρητά οι επιλογές σχετικά με την τοποθεσία των δεδομένων, τη διάρκεια διατήρησής τους και τον πάροχο υπηρεσιών αποθήκευσης·
- να επιτρέπεται στους φορείς να διαχειρίζονται τις δικές τους συμβατές λύσεις αποθήκευσης ή ανάπτυξης, όπου απαιτείται·
- διατήρηση φορητών τοπικών αρχείων και εύκολη εξαγωγή ανά πάσα στιγμή.

## Προτεινόμενη τοπολογία υπηρεσιών

Μια εφαρμογή σε κλίμακα παραγωγής μπορεί να διαχωρίσει τη διαδραστική παροχή περιεχομένου από τη μόνιμη αποθήκευση και την επεξεργασία στο παρασκήνιο:

```text
Clients: Web · Windows · Linux · macOS · Android · iOS/iPadOS
                              │
                         CDN / ingress
                              │
                         Studio API
          ┌───────────────────┼───────────────────┐
          │                   │                   │
     identity/session    manuscript/workspace   integrations
          │                   │                   │
          └──────────── PostgreSQL ──────────────┘
                              │
                    S3-compatible object store
                              │
                    queue / background workers
                              │
          PDF · DOCX · export · validation · indexing
```

Ο συγκεκριμένος πάροχος υπηρεσιών cloud δεν περιλαμβάνεται σκόπιμα στις προδιαγραφές του «OMI». Η αρχιτεκτονική θα πρέπει να βασίζεται σε φορητές διεπαφές και πρότυπα ανάπτυξης και όχι σε ιδιόκτητη σημασιολογία αποθήκευσης.

## Αποθήκευση εγγράφων συνδεδεμένων με λογαριασμό

Στη λειτουργία «OMI» Cloud με διαχείριση, ένας λογαριασμός χρήστη μπορεί να είναι κάτοχος ή να συμμετέχει σε έναν ή περισσότερους χώρους εργασίας. Ένας χώρος εργασίας μπορεί να περιέχει χειρόγραφα, στοιχεία περιουσίας, ιστορικό εκδόσεων, προϊόντα εξαγωγής και μεταδεδομένα ελέγχου πρόσβασης.

Μια χρήσιμη λογική ιεραρχία είναι:

```text
OMI Account
  └─ Workspace
      └─ Manuscript
          ├─ Versions
          ├─ Assets
          ├─ Review/collaboration state
          └─ Exports
```

Τα δομημένα μεταδεδομένα, τα δικαιώματα πρόσβασης, η κατάσταση συνεργασίας και οι αναφορές σε εκδόσεις συναλλαγών πρέπει να αποθηκεύονται σε μια βάση δεδομένων όπως το PostgreSQL. Τα μεγαλύτερα αμετάβλητα ή δυαδικά αντικείμενα — αρχεία πηγαίου κώδικα DOCX/PDF, εικόνες, συσκευασμένες εξαγωγές και άλλα στοιχεία — ταιριάζουν καλύτερα σε αποθήκευση αντικειμένων συμβατή με το S3.

## Επεξεργασία στο παρασκήνιο και ελαστικότητα

Η επεξεργασία εγγράφων που διαρκεί για μεγάλο χρονικό διάστημα δεν πρέπει να διατηρεί ανοιχτό ένα διαδραστικό αίτημα HTTP. Η ανασυγκρότηση μεγάλων αρχείων τύπου «PDF», η μετατροπή αρχείων τύπου «DOCX», η απόδοση δημοσιεύσεων, η επικύρωση, η ευρετηρίαση, καθώς και μελλοντικές ενσωματώσεις που απαιτούν μεγάλη υπολογιστική ισχύ μπορούν να αντιπροσωπευθούν ως εργασίες.

Για παράδειγμα:

```text
Upload → Queued → Processing → Structural reconstruction → Validation → Ready
```

Οι χρήστες μπορούν να πραγματοποιούν οριζόντια κλιμάκωση ανάλογα με το μέγεθος της ουράς αναμονής. Αυτό διαχωρίζει τις απαιτητικές εισαγωγές από την κανονική κίνηση επεξεργασίας και καθιστά την υπηρεσία κατάλληλη για χρήση από μεγαλύτερους οργανισμούς, χωρίς να απαιτείται επανασχεδιασμός του μοντέλου χειρογράφου.

## Κυριαρχία δεδομένων και ομοσπονδία

OMI Το cloud πρέπει να σχεδιαστεί έτσι ώστε η διαχειριζόμενη φιλοξενία να είναι βολική, αλλά ποτέ υποχρεωτική. Τρεις τρόποι αποθήκευσης πρέπει να παραμείνουν ως βασικές επιλογές:

1. **local-first** — τα φορητά έγγραφα `.omi` παραμένουν στη συσκευή του χρήστη ή στο σύστημα αρχείων της επιλογής του·
2. **Διαχειριζόμενο Cloud της OMI** — ο αποθηκευτικός χώρος και ο συγχρονισμός που συνδέονται με τον λογαριασμό παρέχονται από έναν πάροχο υπηρεσιών του OMI·
3. **θεσμικός/ομοσπονδιακός χώρος αποθήκευσης** — ένας φορέας μπορεί να χρησιμοποιεί το δικό του συμβατό αποθετήριο αντικειμένων, ιδιωτικό cloud ή περιβάλλον ανάπτυξης, συνεχίζοντας παράλληλα να χρησιμοποιεί τους πελάτες του προτύπου «OMI» και τις μορφές ανταλλαγής δεδομένων.

Εξωτερικοί πάροχοι, όπως το Nextcloud/WebDAV, το OneDrive, το Google Drive ή άλλες υπηρεσίες που επιλέγει ο χρήστης, μπορούν να παραμείνουν ως επιπλέον στόχοι ενσωμάτωσης. Η επιλογή του παρόχου δεν πρέπει να επαναπροσδιορίζει το μοντέλο του επιστημονικού αντικειμένου.

Όσον αφορά τις εγκαταστάσεις σε ευρωπαϊκά ιδρύματα, ο οδικός χάρτης προτιμά επιλογές διατήρησης δεδομένων εντός της ΕΕ/ΕΟΧ, ρητούς κανόνες διατήρησης, κρυπτογράφηση τόσο κατά τη μεταφορά όσο και κατά την αποθήκευση, δυνατότητα ελέγχου, δυνατότητα εξαγωγής, διαγραφή λογαριασμού και διακυβέρνηση προσαρμοσμένη στα συγκεκριμένα ιδρύματα. Πρόκειται για απαιτήσεις εγκατάστασης και όχι για αλλαγές στη σημασιολογία των χειρογράφων του περιοδικού «OMI».

## Αποφυγή της εξάρτησης από έναν συγκεκριμένο προμηθευτή

Μια υπηρεσία cloud δεν πρέπει να υπονομεύει τις εγγυήσεις φορητότητας που αποτέλεσαν το κίνητρο για τη δημιουργία του OMI. Ως εκ τούτου, η αρχιτεκτονική δίνει προτεραιότητα στα εξής:

- Διεπαφές αντικειμένων συμβατές με το S3 αντί για αποκλειστικές του προμηθευτή, όπου αυτό είναι εφικτό·
- τυποποιημένη αποθήκευση συναλλαγών συμβατή με το PostgreSQL·
- τεκμηριωμένες μορφές εξαγωγής και δημιουργίας αντιγράφων ασφαλείας·
- φορητά πακέτα «`.omi`» ως μια αξιόπιστη λύση διαφυγής·
- ρητές αφαιρέσεις παρόχων αποθήκευσης στο backend του Studio·
- διαχωρισμός μεταξύ της ταυτότητας του χειρογράφου και της τοποθεσίας της υποδομής.

Ο στόχος είναι να καταστεί ευκολότερη η λειτουργία του OMI σε μεγάλη κλίμακα, χωρίς να δημιουργηθεί ένα νέο κλειστό σύστημα αποθήκευσης χειρογράφων.

## Θεσμικοί χώροι εργασίας

Οι εγκαταστάσεις σε επίπεδο ιδρύματος μπορούν να βασίζονται στον υπάρχοντα διαχωρισμό μεταξύ προσωπικών λογαριασμών, ταυτότητας των επιστημονικών συντελεστών, ιδιότητας μέλους του ιδρύματος και κεντρικής διοίκησης. Οι χώροι εργασίας στο cloud θα πρέπει να ακολουθούν το ίδιο όριο: η διοικητική εξουσία επί ενός ιδρύματος ή μιας υπηρεσίας δεν πρέπει να παρέχει αυτόματα πρόσβαση σε εμπιστευτικά χειρόγραφα, υλικό αξιολόγησης από ομοτίμους ή συντακτικό περιεχόμενο.

Οι θεσμικοί χώροι εργασίας μπορούν στη συνέχεια να υποστηρίξουν όρια χωρητικότητας, πολιτικές διατήρησης, ανατεθειμένη αποθήκευση, δικαιώματα ομάδων, ροές εργασιών εκδοτών και χώρους ερευνητικών έργων, χωρίς να αλλάξει η υποκείμενη μορφή των εγγράφων.

## Διαδρομή μετεγκατάστασης από την τρέχουσα εγκατάσταση

Η μετάβαση θα πρέπει να γίνει σταδιακά και όχι με μια ριζική αναδιαμόρφωση του κώδικα. Οι νέες δυνατότητες του backend θα πρέπει να υλοποιηθούν με βάση αντικαταστάσιμες αφαιρέσεις αποθήκευσης και εργασιών, έτσι ώστε η τρέχουσα εγκατάσταση να μπορεί να συνεχίσει να λειτουργεί κατά την εισαγωγή στοιχείων που είναι συμβατά με το cloud.

Μια πρακτική ακολουθία είναι:

1. να ορίσουμε μια αφαίρεση παροχέα αποθήκευσης γύρω από την υφιστάμενη μόνιμη αποθήκευση από την πλευρά του διακομιστή·
2. να προστεθεί αποθήκευση αντικειμένων συμβατή με το S3 για αρχεία μεγάλου μεγέθους και εξαγωγές·
3. μεταφορά των χρονοβόρων εργασιών εισαγωγής/εξαγωγής σε μια ανθεκτική ουρά και σε μια διεργασία-εργάτη·
4. να εισαγάγει τη διατήρηση εγγράφων στο cloud που συνδέονται με τον χώρο εργασίας και τις αναφορές σε εκδόσεις·
5. προσθήκη διαμόρφωσης και ομοσπονδίας θεσμικών παρόχων αποθήκευσης·
6. να αναπτύξετε εφεδρικές/χωρίς κατάσταση (stateless) παρουσίες του API πίσω από το διαχειριζόμενο ingress, όταν το απαιτεί ο λειτουργικός φόρτος.

## Σημασία της χρηματοδότησης και της βιωσιμότητας

Μια επεκτάσιμη ομοσπονδιακή υποδομή αποτελεί επίσης μια στρατηγική κατεύθυνση για τις ερευνητικές υποδομές. Μπορεί να υποστηρίξει πιλοτικά προγράμματα στα οποία συμμετέχουν πολλά ιδρύματα, πανεπιστημιακούς εκδοτικούς οίκους, επιστημονικές εταιρείες και προγράμματα ανοικτής επιστήμης, διατηρώντας παράλληλα ανοικτές τις βασικές προδιαγραφές και την εφαρμογή αναφοράς του «OMI».

Η σταθερή ευρωπαϊκή ή θεσμική χρηματοδότηση θα επέτρεπε τη μετάβαση από τη σημερινή συμπαγή, φιλοξενούμενη ανάπτυξη προς μια ανθεκτική υπηρεσία πολλαπλών χρηστών με φιλοξενία στην ΕΕ/ΕΟΧ, επιχειρησιακή ασφάλεια, παρακολούθηση, δημιουργία αντιγράφων ασφαλείας, αποκατάσταση μετά από καταστροφή και θεσμική ομοσπονδία. Ο οδικός χάρτης **δεν** προϋποθέτει ότι η εν λόγω χρηματοδότηση έχει ήδη εξασφαλιστεί.

## Κατάσταση

Αυτή η σελίδα περιγράφει μια **προγραμματισμένη αρχιτεκτονική και μια κατεύθυνση ανάπτυξης υποδομής που εξαρτάται από τη χρηματοδότηση**, και όχι έναν ισχυρισμό ότι η πλήρης υπηρεσία «OMI» στο Cloud έχει ήδη τεθεί σε λειτουργία. Ο υπάρχων τοπικός χώρος αποθήκευσης, οι εγγενείς ροές εργασίας αρχείων, οι συνδέσεις στο cloud με πεδίο εφαρμογής το προφίλ, η υποδομή λογαριασμών και η λειτουργία «API» του Studio αποτελούν τα θεμέλια υλοποίησης για αυτό το μελλοντικό βήμα.
