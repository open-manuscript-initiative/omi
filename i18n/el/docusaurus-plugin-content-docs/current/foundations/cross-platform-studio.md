# Αρχιτεκτονική Studio για όλες τις πλατφόρμες

Open Manuscript Studio έχει σχεδιαστεί ως ένα ενιαίο περιβάλλον δημιουργίας επιστημονικού περιεχομένου που λειτουργεί σε διαδικτυακές, επιτραπέζιες και κινητές συσκευές, χωρίς να κατακερματίζει το μοντέλο του χειρογράφου ή την υλοποίηση της ροής εργασίας.

Το έργο δεν διατηρεί ξεχωριστές εφαρμογές για κάθε λειτουργικό σύστημα. Το Studio χρησιμοποιεί έναν κοινό πυρήνα εφαρμογής React/TypeScript και ένα κοινό μοντέλο εγγράφου OMI, ενώ τα λεπτά στρώματα που είναι ειδικά για κάθε πλατφόρμα παρέχουν εγγενείς δυνατότητες όπου απαιτείται.

## Κατάσταση πλατφόρμας

| Πλατφόρμα | Τρέχουσα κατάσταση | Κατεύθυνση παράδοσης |
|---|---|---|
| Ιστό | **Λειτουργικό** | Φιλοξενούμενο στούντιο |
| Windows | **Λειτουργικό** | Tauri 2 EXE/MSI |
| macOS | **Αυτοματοποιημένος στόχος κατασκευής** | DMG για Intel και Apple Silicon· παραμένουν οι ενισχύσεις ασφαλείας για την υπογραφή/επικύρωση |
| Linux | **Αυτοματοποιημένος στόχος κατασκευής** | AppImage και DEB |
| Android | **Λειτουργική δημόσια έκδοση άλφα** | Παγκόσμιο APK από τη ροή εργασιών κοινής κυκλοφορίας· συσκευασία προσαρμοσμένη στα καταστήματα θα ακολουθήσει |
| iOS / iPadOS | **Επικυρωμένος στόχος δημιουργίας εγγενούς έκδοσης** | Η δημιουργία έκδοσης για τον προσομοιωτή iPhone/iPad ολοκληρώνεται με επιτυχία· η διανομή μέσω TestFlight/App Store απαιτεί υπογραφή από την Apple Developer και τελική συσχέτιση με το Universal Link |

Το Android δεν αποτελεί πλέον μόνο έναν στόχο αρχιτεκτονικής ή ανάπτυξης. Δημιουργείται ένα δημόσιο, καθολικό APK από τον κοινό κώδικα του Tauri 2, το οποίο χρησιμοποιεί την ίδια λογική για λογαριασμούς, έγγραφα, έλεγχο, ενσωμάτωση και εξαγωγή όπως και οι άλλοι πελάτες, με προσαρμοσμένη εμφάνιση ειδικά για κινητά και διαχείριση αρχείων μέσω του εγγενούς πλαισίου πρόσβασης σε έγγραφα και αποθηκευτικό χώρο (Documents/Storage Access Framework) του Android.

Το iOS/iPadOS έχει επίσης προχωρήσει πέρα από τον σχεδιασμό που αφορά αποκλειστικά την αρχιτεκτονική. Το CI δημιουργεί πλέον το έργο Tauri/Xcode, μεταγλωττίζει την εφαρμογή προσομοιωτή iPhone/iPad για Apple Silicon και ανεβάζει το τελικό αρχείο του προσομοιωτή. Το μόνο εμπόδιο που απομένει και αφορά αποκλειστικά την Apple είναι η φυσική συσκευή και η δημόσια διανομή: απαιτούνται ακόμη η πραγματική υπογραφή από το Apple Developer, η προμήθεια, η συσχέτιση με το Universal Link και η επικύρωση μέσω TestFlight/App Store, προτού καταστεί δυνατή η δημόσια κυκλοφορία μιας έκδοσης για iOS.

## Ένας πυρήνας Studio

```text
                         OMI Studio Core
                                │
               ┌────────────────┼────────────────┐
               │                │                │
             Web UI         Desktop UI       Mobile UI
               │                │                │
            Browser           Tauri 2          Tauri 2
                                │                │
                      ┌─────────┼─────────┐   ┌──┴────┐
                    Windows    macOS    Linux Android iOS/iPadOS
```

Ο κοινός πυρήνας περιλαμβάνει, όπου αυτό είναι τεχνικά εφικτό:

- το μοντέλο επιστημονικού χειρογράφου «OMI»·
- δομημένη επεξεργασία και συμπεριφορά εγγράφων με βάση το Tiptap·
- μεταδεδομένα, συνεισφέροντες, παραπομπές, σχολιασμοί και λογική διαχείρισης εκδόσεων·
- πολυγλωσσική διεπαφή και υποστήριξη δημιουργίας περιεχομένου·
- διαδικασίες ελέγχου ταυτότητας, ανάκτησης κωδικού πρόσβασης και διαχείρισης συνδεδεμένων ταυτοτήτων·
- συμπεριφορά κατά τη διπλά τυφλή αξιολόγηση από ομότιμους·
- OJS καθώς και ροές εργασίας ενσωμάτωσης OMP·
- πελάτες που αφορούν τη συμμετοχή σε ιδρύματα και τη διοίκηση·
- λογική εισαγωγής, εξαγωγής και προφίλ δημοσίευσης·
- κανόνες επικύρωσης, ενοποίησης και αποθήκευσης.

Επομένως, μια λειτουργία που έχει υλοποιηθεί στον κοινό πυρήνα θα πρέπει να είναι διαθέσιμη σε κάθε υποστηριζόμενη πλατφόρμα, εκτός εάν το λειτουργικό σύστημα ή ο τύπος συσκευής απαιτεί διαφορετική παρουσίαση ή εγγενή υλοποίηση.

## Επίπεδο προσαρμογέα πλατφόρμας

Οι εγγενείς υπηρεσίες του λειτουργικού συστήματος απομονώνονται πίσω από προσαρμογείς πλατφόρμας, αντί να ενσωματώνονται σε ολόκληρο τον επεξεργαστή ή το επιστημονικό μοντέλο. Σύγχρονα παραδείγματα περιλαμβάνουν την εγγενή επιλογή φακέλων/αρχείων, τα εγγενή παράθυρα διαλόγου αποθήκευσης, την πρόσβαση σε Android Documents/SAF, την πρόσβαση σε Apple Files/UIDocumentPicker, τις εγγραφές στο σύστημα αρχείων, τη μόνιμη ή περιορισμένη από άποψη ασφάλειας πρόσβαση στο σύστημα αρχείων που παραχωρείται από τον χρήστη, τη συμπεριφορά του προγράμματος ενημέρωσης της επιφάνειας εργασίας και την εγγενή μεταβίβαση εξωτερικής πιστοποίησης.

Η εγγενής πιστοποίηση χρησιμοποιεί τον τρόπο μεταφοράς που είναι κατάλληλος για την προέλευση της εφαρμογής. Οι πελάτες Tauri μπορούν να χρησιμοποιούν μεταφορά τύπου «bearer-session» και να μοιράζονται ροές μεταβίβασης εξωτερικής πιστοποίησης μίας χρήσης για το ORCID και για διαμορφωμένους παρόχους OIDC, αντί να βασίζονται αποκλειστικά σε cookies του προγράμματος περιήγησης.

## Διεπαφές για επιτραπέζιους υπολογιστές και κινητά

Ο όρος «διαπλατφορμικός» δεν σημαίνει ότι πρέπει να επιβάλλουμε την ίδια διάταξη οθόνης σε κάθε συσκευή.

Το Desktop Studio υποστηρίζει πλέον καρτέλες πολλαπλών εγγράφων τύπου προγράμματος περιήγησης, επιφάνειες Studio/Account πλήρους παραθύρου και μια επιλογή εμφάνισης/απόκρυψης περιλήψεως εγγράφου τύπου Word δίπλα στον επεξεργαστή. Το Mobile Studio χρησιμοποιεί την ίδια λογική χειρογράφου και επεξεργασίας, αλλά την παρουσιάζει μέσω πλοήγησης προσανατολισμένης στην αφή, συμπαγών στοιχείων ελέγχου, συρταριών και ανταποκρινόμενων πλαισίων. Τα tablet μπορούν να επαναφέρουν σταδιακά την επεξεργασία σε πολλαπλά πάνελ, όπου το επιτρέπει το μέγεθος της οθόνης.

Οι τρέχουσες εργασίες για κινητές συσκευές περιλαμβάνουν προσαρμοστική πλοήγηση, προβολές εγγράφων και λεπτομερειών, πρόσβαση σε λογαριασμό/προφίλ, στοιχεία ελέγχου εισαγωγής, αναζήτηση, αλλαγή γλώσσας, αποσύνδεση, διαχείριση επιστροφής μέσω του ενσωματωμένου προγράμματος περιήγησης της εφαρμογής για τα πρωτόκολλα ORCID/OIDC, άνοιγμα/αποθήκευση μέσω εγγενών παροχέων αρχείων, εγγενή εξαγωγή και συνεπή επωνυμία OMI Studio. Το Android χρησιμοποιεί το Documents/SAF, ενώ το iPhone/iPad χρησιμοποιεί το Files/UIDocumentPicker. Πρόκειται για ζητήματα παρουσίασης και πλατφόρμας, τα οποία δεν απαιτούν ξεχωριστά μοντέλα χειρογράφων για Android ή Apple.

## Προτεραιότητα στην τοπική φορητότητα και αξιοπιστία συσκευών

Το μοντέλο πολλαπλών πλατφορμών ενισχύει μια βασική αρχή του «OMI»: το χειρόγραφο δεν πρέπει να εξαρτάται από την εγκατάσταση μιας συγκεκριμένης εφαρμογής, από έναν συγκεκριμένο πάροχο υπηρεσιών cloud ή από ένα συγκεκριμένο λειτουργικό σύστημα.

Ένα χειρόγραφο που έχει δημιουργηθεί σε Windows θα πρέπει να είναι χρησιμοποιήσιμο σε Linux, macOS, Android, iOS/iPadOS ή στον περιηγητή χωρίς να απαιτείται μετατροπή σε μοντέλο εγγράφου ειδικό για κάθε πλατφόρμα. Οι φορές «`.omi.zip`» και «OMI» JSON παρέχουν ρητούς στόχους ανταλλαγής, ενώ οι υπηρεσίες διακομιστή χρησιμοποιούνται μόνο όπου απαιτούνται για λόγους ταυτότητας, συνεργασίας, ροών εργασίας δημοσίευσης ή άμεσων ενσωματώσεων.

Οι εγκατεστημένοι πελάτες προσθέτουν πλέον μια διάκριση εμπιστοσύνης σε τοπικό επίπεδο της συσκευής.

### Δική σας συσκευή

Όταν ο συνδεδεμένος χρήστης επισημάνει μια εγκατεστημένη συσκευή ως δική του, το Studio μπορεί να διατηρήσει τις συνήθεις εγγενείς τοποθεσίες των αρχείων εργασίας. Οι προορισμοί για επιτραπέζιους υπολογιστές μπορούν να χρησιμοποιούν τοπικούς φακέλους, συνδεδεμένους/δικτυακούς χώρους αποθήκευσης και φακέλους που συγχρονίζονται από πελάτες επιτραπέζιων υπολογιστών παρόχων. Το Android μπορεί να χρησιμοποιεί προορισμούς «Documents/SAF» που επιλέγονται από το σύστημα, ενώ το iPhone/iPad μπορεί να χρησιμοποιεί τοποθεσίες «Files/UIDocumentPicker» που επιλέγονται από το σύστημα, συμπεριλαμβανομένου του iCloud Drive και διαθέσιμων παρόχων εγγράφων τρίτων κατασκευαστών.

### Κοινόχρηστη ή εξωτερική συσκευή

Οι συσκευές που εντοπίζονται για πρώτη φορά ρυθμίζονται εξ ορισμού σε λειτουργία «κοινόχρηστη/ξένη συσκευή». Σε αυτή τη λειτουργία, το Studio δεν διατηρεί την επιλεγμένη διαδρομή του τοπικού αρχείου εργασίας. Η συνήθης μόνιμη ροή εργασίας προτιμά τις συνδέσεις στο cloud που ανήκουν στο προφίλ με το οποίο έχει γίνει σύνδεση.

Ο χρήστης μπορεί ακόμα να ανοίξει ή να αποθηκεύσει ρητά ένα αρχείο σε αφαιρούμενο/φορητό μέσο αποθήκευσης ή σε άλλη θέση εγγράφων που παρέχει το σύστημα, αλλά η θέση αυτή αντιμετωπίζεται ως εφάπαξ προορισμός και δεν αποθηκεύεται ως το τρέχον αρχείο εργασίας.

Με αυτόν τον τρόπο αποφεύγεται η ψευδαίσθηση ότι η ανίχνευση φορητών αφαιρούμενων δίσκων είναι πανομοιότυπη σε όλα τα λειτουργικά συστήματα, ενώ παράλληλα διατηρείται η σημαντική ιδιότητα ασφάλειας: οι τοπικές διαδρομές των κοινόχρηστων συσκευών δεν αποθηκεύονται.

## Συγχρονισμένοι φάκελοι ανά πάροχο

Το Desktop Studio αντιμετωπίζει έναν τοπικά συγχρονισμένο φάκελο ως μέθοδο σύνδεσης του πραγματικού παρόχου και όχι ως έναν γενικό ψευδο-πάροχο.

Για το OneDrive, το SharePoint, το Google Drive, το Dropbox, το Nextcloud, το iCloud Drive και παρόμοιους παρόχους υπηρεσιών συγχρονισμού με τον υπολογιστή:

- ο ίδιος ο πελάτης του παρόχου πραγματοποιεί την πιστοποίηση και τον συγχρονισμό·
- Το Studio δεν λαμβάνει ποτέ τον κωδικό πρόσβασης του παρόχου ή το διακριτικό «OAuth» για αυτή τη λειτουργία·
- ο χρήστης επιλέγει έναν φάκελο που έχει συγχρονιστεί με τον πάροχο μέσω του εγγενούς διαλόγου·
- η διαδρομή παραμένει τοπική για κάθε συσκευή και απομονώνεται ανά συνδεδεμένο χρήστη/πάροχο/τύπο λογαριασμού·
- το εύρος του συστήματος αρχείων που έχει παραχωρηθεί από τον χρήστη μπορεί να παραμείνει σε μια δική του συσκευή·
- Το Studio δημιουργεί φορητά αρχεία τύπου «OMI», ενώ ο πελάτης του παρόχου αναλαμβάνει τον συγχρονισμό μέσω δικτύου.

Οι απευθείας συνδέσεις WebDAV/Nextcloud εξακολουθούν να αποτελούν ξεχωριστή ενσωμάτωση διακομιστή σε επίπεδο προφίλ με κρυπτογραφημένα διαπιστευτήρια.

## Ροή εργασιών αρχείων εγγενής στο Android

Το Android χρησιμοποιεί το περιβάλλον εργασίας «Documents / Storage Access Framework» του συστήματος αντί για γενικά δικαιώματα πρόσβασης σε κοινόχρηστο χώρο αποθήκευσης.

Η τρέχουσα ροή εργασιών του Android υποστηρίζει:

- το άνοιγμα ενός υπάρχοντος εγγράφου του OMI μέσω του εργαλείου επιλογής συστήματος·
- Αποθήκευση στον τρέχοντα επιλεγμένο προορισμό εγγράφου·
- Αποθήκευση σε άλλη θέση·
- φορητή συσκευή δημιουργίας αντιγράφων ασφαλείας `.omi.zip`;
- Μορφές εξαγωγής που σχετίζονται με το Android, όπως OMI JSON/package, JATS XML, HTML package, DOCX, LaTeX και EPUB.

Οι ακατέργαστοι αναγνωριστικοί του «`content://`» αποτελούν λεπτομέρειες υλοποίησης και δεν εμφανίζονται στον χρήστη ως συνήθεις διαδρομές του συστήματος αρχείων.

## Ροή εργασιών αρχείων εγγενής στο iOS/iPadOS

Το iPhone και το iPad χρησιμοποιούν τη διεπαφή «Apple Files / UIDocumentPicker» αντί για ευρεία πρόσβαση στο σύστημα αρχείων. Οι λειτουργίες ανοίγματος απαιτούν πρόσβαση σε έγγραφα εντός του πλαισίου ασφαλείας, ενώ το επίπεδο συστήματος αρχείων του Tauri διαβάζει/γράφει τη διεύθυνση URL `file://` που έχει επιλέξει ο χρήστης.

Ανάλογα με τους εγκατεστημένους παρόχους και τη διαμόρφωση της συσκευής, το εργαλείο επιλογής μπορεί να εμφανίζει:

- Στο iPhone μου / Στο iPad μου;
- iCloud Drive;
- συνδεδεμένη εξωτερική συσκευή αποθήκευσης που υποστηρίζεται από το iOS/iPadOS·
- αρχεία τρίτων παρόχων που παρέχονται από εγκατεστημένες εφαρμογές αποθήκευσης στο cloud.

Η εφαρμογή για iOS/iPadOS χρησιμοποιεί το ίδιο σύνολο επιλογών εξαγωγής για κινητά με το Android: OMIpackage/,JSON, JATSXML, HTMLpackage, DOCX, LaTeX και EPUB. Οι επιλογές που προορίζονται για επιτραπέζιους υπολογιστές —IDML, XTG, MIF, SLA και browserprint/PDF— παραμένουν κρυφές, αντί να εμφανίζονται ως μη λειτουργικές ενέργειες για κινητά.

Για λεπτομέρειες σχετικά με τη δημιουργία, την υπογραφή και τα Universal Links ειδικά για την Apple, ανατρέξτε στη διεύθυνση [Open Manuscript Studio on iOS and iPadOS](./ios-ipados-studio.md).

## Ταυτότητα λογαριασμού σε όλες τις πλατφόρμες

Ο ίδιος λογαριασμός Studio έχει σχεδιαστεί ώστε να λειτουργεί σε προγράμματα περιήγησης, επιτραπέζιους υπολογιστές και κινητές συσκευές. Οι τρέχουσες λειτουργίες κοινής ταυτότητας περιλαμβάνουν:

- κωδικός πρόσβασης: εγγραφή/σύνδεση/αποσύνδεση;
- διαδικασία επαναρύθμισης κωδικού πρόσβασης μίας χρήσης με ημερομηνία λήξης·
- ORCID σύνδεση/σύνδεση λογαριασμού;
- Google, Microsoft και το προσαρμόσιμο θεσμικό OpenID Connect·
- διαχείριση μεθόδων σύνδεσης με προστασία από τον αποκλεισμό·
- δεδομένα προσωπικού προφίλ, διαχωρισμένα από τις ιδιότητες μέλους που αφορούν συγκεκριμένα ιδρύματα·
- Τα δικαιώματα πρόσβασης σε ιδρύματα και στην κεντρική διοίκηση διαχωρίζονται από τα δικαιώματα πρόσβασης στα χειρόγραφα.

Οι ταυτότητες των εξωτερικών παρόχων συνδέονται με βάση τη σταθερή ταυτότητα εκδότη/υποκειμένου και όχι με βάση το εμφανιζόμενο όνομα, ενώ οι υπάρχοντες λογαριασμοί δεν συγχωνεύονται αυτόματα μόνο και μόνο λόγω ταύτισης της διεύθυνσης ηλεκτρονικού ταχυδρομείου.

Οι πελάτες κινητών συσκευών χρησιμοποιούν μια εφάπαξ μεταβίβαση εγγενής πιστοποίησης. Η προτιμώμενη διεύθυνση επιστροφής της εφαρμογής HTTPS φιλοξενείται στη διεύθυνση `app.openmanuscript.org`, ενώ το προσαρμοσμένο σχήμα `openmanuscript://` διατηρείται ως εφεδρική επιλογή. Στο iOS/iPadOS, η διεύθυνση επιστροφής HTTPS σε περιβάλλον παραγωγής απαιτεί επιπλέον τη σύνδεση μέσω Apple Universal Link με το πραγματικό Apple Development Team ID.

## Παράδοση εξαγωγών σε όλες τις πλατφόρμες

Το επίπεδο εξαγωγής διαχωρίζει τη **δημιουργία μορφής** από την **παράδοση αρχείων**.

Το Hosted Studio χρησιμοποιεί συνήθεις λήψεις μέσω του προγράμματος περιήγησης. Οι εγκατεστημένες εφαρμογές για επιτραπέζιους υπολογιστές χρησιμοποιούν εγγενή παράθυρα διαλόγου αποθήκευσης και εγγραφές στο σύστημα αρχείων σε δυαδική μορφή. Το Android χρησιμοποιεί προορισμούς στο φάκελο «Documents/SAF», ενώ το iOS/iPadOS χρησιμοποιεί προορισμούς στο φάκελο «Files/UIDocumentPicker». Και οι δύο πλατφόρμες κινητών συσκευών περιορίζουν σκόπιμα την ορατή λίστα εξαγωγής σε μορφές που είναι συμβατές με την εκάστοτε πλατφόρμα.

Με αυτόν τον τρόπο διατηρείται μία ενιαία εφαρμογή εξαγωγής για τις ακαδημαϊκές μορφές, ενώ παράλληλα επιτρέπεται σε κάθε πλατφόρμα να χρησιμοποιεί τον κατάλληλο μηχανισμό παράδοσης αρχείων.

## Υπηρεσίες κοινών λογαριασμών και ροών εργασίας

Οι εφαρμογές ιστού και οι εγγενείς πελάτες χρησιμοποιούν το ίδιο όριο υπηρεσίας του Studio για την ταυτότητα λογαριασμού, τη συμμετοχή σε ιδρύματα, την αξιολόγηση από ομοτίμους και τις εξωτερικές ενσωματώσεις. Η αρχιτεκτονική διαχωρίζει τέσσερις τομείς:

1. **ακαδημαϊκή κατάσταση** — χειρόγραφο, μεταδεδομένα, συνεισφέροντες, σχολιασμοί και περιεχόμενο κριτικής·
2. **ταυτότητα/κατάσταση υπηρεσίας** — λογαριασμοί, συνεδρίες και δεδομένα συνεργασίας που υποστηρίζονται από διακομιστή·
3. **οργανωτική αρχή** — ιδιότητα μέλους του ιδρύματος και κεντρική διοίκηση·
4. **δυνατότητες πλατφόρμας** — εγγενής πρόσβαση σε αρχεία, δημιουργία πακέτων, συμπεριφορά του προγράμματος ενημέρωσης και ενσωμάτωση στο περιβάλλον εργασίας κινητών συσκευών/επιτραπέζιων υπολογιστών.

Αυτός ο διαχωρισμός είναι σημαντικός για τη φορητότητα: η μετάβαση από τον περιηγητή σε Windows, Android ή iPad δεν επαναπροσδιορίζει το χειρόγραφο ή το πρωτόκολλο αξιολόγησης από ομότιμους, ενώ η ανάληψη του ρόλου του διαχειριστή ενός ιδρύματος δεν παρέχει αυτόματα πρόσβαση σε επιστημονικό περιεχόμενο.

## Πολυγλωσσικές και περιφερειακές ρυθμίσεις

Ο κοινόχρηστος πελάτης διαθέτει επί του παρόντος 24 ευρωπαϊκές γλώσσες διεπαφής χρήστη. Οι προτιμήσεις για τη γλώσσα διεπαφής, τη γλώσσα του κειμένου και τη γλώσσα των μεταδεδομένων διαχειρίζονται από κοινού σε μια συμπαγή και προσαρμοστική επιφάνεια ρυθμίσεων. Οι ζώνες ώρας χρησιμοποιούν τυποποιημένους αναγνωριστικούς κωδικούς IANA με διαφορές ώρας ως προς το UTC και ανίχνευση της ζώνης ώρας του συστήματος, αντί για τιμές ελεύθερου κειμένου, ώστε οι προτιμήσεις του λογαριασμού να παραμένουν μεταφερόμενες μεταξύ των λειτουργικών συστημάτων.

## Κατεύθυνση της ροής εργασίας σε κινητές συσκευές

Οι εφαρμογές για κινητά έχουν σχεδιαστεί για να υποστηρίζουν την ενεργή επιστημονική εργασία και όχι την παθητική ανάγνωση. Οι κοινές λειτουργίες περιλαμβάνουν τη σύνδεση στο λογαριασμό και την πρόσβαση σε χειρόγραφα, τη δομημένη επεξεργασία, την πλοήγηση στα έγγραφα και την επεξεργασία μεταδεδομένων, τους ρόλους συγγραφέα/επιμελητή/κριτή, τη διπλά τυφλή αξιολόγηση από ομοτίμους, την πρόσβαση στη ροή εργασιών του συστήματος έκδοσης, την εισαγωγή/εξαγωγή εγγράφων σε φυσική μορφή και τις δυνατότητες ασφαλούς πλατφόρμας.

Στο μέλλον, οι εγγενείς δυνατότητες ενδέχεται να περιλαμβάνουν πιο εκτεταμένη λειτουργία εκτός σύνδεσης, πλουσιότερες ροές εργασιών για κοινή χρήση/άνοιγμα με άλλες εφαρμογές, βιομετρικά στοιχεία και ειδοποιήσεις push, χωρίς να μεταφέρονται αυτά τα στοιχεία στο μοντέλο εγγράφων του «OMI».

## Μηχανική κυκλοφορίας

Η αυτοματοποίηση κυκλοφορίας δημιουργεί πακέτα για Windows, Linux, macOS και Android από το κοινόχρηστο αποθετήριο. Το iOS/iPadOS διαθέτει πλέον μια δοκιμαστική έκδοση προσομοιωτή που ενεργοποιείται μέσω PR, η οποία δημιουργεί το έργο Xcode, μεταγλωττίζει την εφαρμογή προσομοιωτή Apple Silicon και αποθηκεύει το πακέτο της εφαρμογής. Μια ξεχωριστή χειροκίνητη ροή εργασιών έκδοσης της Apple προετοιμάζεται για την υπογεγραμμένη συσκευασία συσκευής/App Store Connect, μόλις παρασχεθούν τα διαπιστευτήρια του Apple Developer.

Η αναπαραγωγιμότητα ενισχύεται χάρη στα γραφήματα εξαρτήσεων του JavaScript και του Rust/Tauri, τα οποία ελέγχονται από αρχεία κλειδώματος, καθώς και στις διαδρομές εγκατάστασης της συνεχούς εντοπισμού σφαλμάτων (CI), οι οποίες αποτρέπουν την απόκλιση των αρχείων κλειδώματος.

Το μοντέλο διανομής διαχωρίζει τη δημιουργία αρχείων από την υποδομή εμπιστοσύνης. Η υπογραφή κώδικα στα Windows, η υπογραφή/επικύρωση στο macOS και η υπογραφή στα καταστήματα εφαρμογών για κινητά της Apple και της Google αποτελούν μέτρα ενίσχυσης της ασφάλειας των εκδόσεων που εφαρμόζονται επιπλέον της κοινής διαδικασίας δημιουργίας εφαρμογών.

## Γιατί αυτό έχει σημασία για τις επιστημονικές εκδόσεις

Η υποστήριξη πολλαπλών πλατφορμών δεν αποτελεί απλώς μια ευκολία στην ανάπτυξη. Οι συγγραφείς, οι κριτές, οι επιμελητές, οι εκδότες και τα ιδρύματα θα πρέπει να μπορούν να συμμετέχουν στην ίδια επιστημονική ροή εργασίας από διαφορετικές συσκευές, χωρίς να δημιουργούν ασυμβίβαστα αντίγραφα του έργου. Η δομή, οι σχολιασμοί, οι παραπομπές, η κατάσταση της κριτικής, τα μεταδεδομένα και η σημασιολογία της δημοσίευσης θα πρέπει να παραμένουν σταθερά όταν ο χρήστης αλλάζει λειτουργικό σύστημα, πάροχο αποθήκευσης ή τύπο συσκευής.

Σε αυτή την αρχιτεκτονική, **το επιστημονικό χειρόγραφο είναι εκ φύσεως φορητό, και η εφαρμογή ακολουθεί το χειρόγραφο αντί να το δεσμεύει στην εφαρμογή.**

## Κατάσταση υλοποίησης

Η παράδοση για το Web και τα Windows αποτελεί λειτουργικό μέρος του Studio, το Android είναι ένας δημόσιος στόχος έκδοσης άλφα, το Linux/macOS είναι αυτοματοποιημένοι στόχοι εγγενούς κατασκευής, ενώ το iOS/iPadOS αποτελεί πλέον έναν επικυρωμένο στόχο εγγενούς κατασκευής για προσομοιωτή στην ίδια αρχιτεκτονική Tauri 2. Ο κοινόχρηστος πελάτης περιλαμβάνει εργασία σε επιφάνεια εργασίας με πολλά έγγραφα, εγγενή αποθήκευση με αναγνώριση συσκευής, διαχείριση Android Documents/SAF, διαχείριση Apple Files/UIDocumentPicker, ταυτότητα λογαριασμού σε όλες τις συσκευές και ομοσπονδιακή πιστοποίηση, εκτός από τη ροή εργασίας του προγράμματος περιήγησης. Η δημόσια διανομή για iOS/iPadOS εξακολουθεί να εξαρτάται από την υπογραφή προγραμματιστή της Apple, την προμήθεια, τη σύνδεση με Universal Link και την επικύρωση μέσω TestFlight/App Store.

Για λεπτομέρειες σχετικά με την τρέχουσα υλοποίηση, ανατρέξτε στις διευθύνσεις [Studio Implementation Status](../governance/studio-implementation-status.md), [Open Manuscript Studio on iOS and iPadOS](./ios-ipados-studio.md), [Integration Implementation Status](../integrations/implementation-status.md) και [Institutional and Central Administration](../integrations/institutional-administration.md).
