# Работен процес за локализация на уебсайта на DeepL

Уебсайтът „OMI“ може да използва DeepL API, за да допълни липсващите преводи на интерфейса Docusaurus и преведената документация, като същевременно английският източник остава авторитетен.

## Сигурност

Ключът „API“ никога не се записва трайно. Задайте го само в текущата командна среда:

```powershell
$env:DEEPL_API_KEY = "YOUR_KEY"
```

или в Linux/macOS:

```bash
export DEEPL_API_KEY="YOUR_KEY"
```

Крайните точки на DeepL Free и Pro се разпознават по ключа. Файлът „`DEEPL_API_URL`“ може да преопредели крайната точка, когато е необходимо.

## Одит без използване на квотата „API“

```bash
npm run i18n:deepl:site:check
```

Този отчет показва кои конфигурирани локали са налични, колко документационни файла са преведени и кои изходни документи все още липсват. Той не използва DeepL и не променя файловете.

## Превеждане на липсващите локализации и документи

```bash
npm run i18n:deepl:site
```

За локализация, която все още не съществува, скриптът първо изпълнява Docusaurus `write-translations`, след което превежда генерираните ресурси от JSON и създава преведени копия на английската документация в стандартната i18n папка Docusaurus.

Съществуващите файлове с документация се запазват. Унгарският и немският език се третират като локали, поддържани ръчно, и никога не се генерират отново с командата ``--force``; от английския източник могат да се добавят само липсващи файлове с документация.

## Избрани локализации

```bash
npm run i18n:deepl:site -- --locales=fr,es,it
```

## Умишлено регенериране на локализации, преведени чрез машинен превод

```bash
npm run i18n:deepl:site -- --locales=fr --force
```

Направете това едва след преглед, тъй като това замества съществуващите машинно преведени страници „JSON“ и документацията за избраната локализация. Ръчно поддържаното съдържание на унгарски и немски език остава защитено.

## Защитено съдържание

Преводачът запазва оградените кодови блокове и избягва превода на импорти/експорти, както и на структурните редове от типа „MDX“. Вграденият код, URL адресите, дестинациите на линковете, заместителите в шаблоните и терминологията на проекта, като например OMI, OJS, OMP, ORCID, ROR, DOI, DOCX, IDML, JATS, CSL, CSS, HTML, PDF, WebAuthn и LaTeX, са защитени от машинен превод.

## Преглед и валидиране

Машинният превод е първоначален вариант, а не окончателен вариант, одобрен от редактора. След генерирането:

1. да прегледа терминологията и езика, използван в научните публикации;
2. проверете Markdown/MDX за правилното изобразяване и вътрешните връзки;
3. изпълни `npm run build`;
4. да се проверят поне началната страница, страницата „Студио“ и няколко страници с документация във всяка новосъздадена локализация;
5. да се правят промени във файловете с преводи на локали едва след преглед.

Английската документация остава източникът за бъдещо генериране на липсващи файлове. Наличните преведени файлове не се презаписват автоматично по време на обичайното изпълнение.
