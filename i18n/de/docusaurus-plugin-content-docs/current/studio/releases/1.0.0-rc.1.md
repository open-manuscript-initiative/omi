# Open Manuscript Studio 1.0.0-rc.1

**4. November 2026: Web Studio und das Android-APK stehen als 1.0.0-rc.1 bereit.**

- [Web Studio RC öffnen](https://studio.openmanuscript.org).
- [Android-RC-Paket herunterladen (ZIP)](https://github.com/open-manuscript-initiative/open-manuscript-studio/actions/runs/41741830930/artifacts/13282507414) aus dem geprüften Build. Eine GitHub-Anmeldung kann erforderlich sein; ZIP entpacken und die enthaltene APK installieren.
- Desktop-Downloads verwenden weiterhin die veröffentlichten [0.3.0-beta.13](https://github.com/open-manuscript-initiative/open-manuscript-studio/releases/tag/v0.3.0-beta.13)-Pakete. Windows-RC-Codesignierung und vollständige Desktop-Abnahme stehen noch aus.

Der Android-RC verwendet den **direkten APK-Kanal**. Damit wird kein RC-Update auf Google Play angekündigt. Ein dauerhaftes GitHub-Release `v1.0.0-rc.1` für alle Plattformen ist ein eigener Veröffentlichungsschritt.

Die [Betreiberbeobachtungen](https://github.com/open-manuscript-initiative/open-manuscript-studio/tree/a3ac0e98194c7d39a0013e280453c7f428d86dd0/docs/release/evidence/1.0.0-rc.1/e1200268ad549c0a40ace8724715cd2405e9d03c) dokumentieren funktionierenden Windows-/Android-/Web-Betrieb, OJS-/OMP-Verbindungen mit Version 3.5.0-5, Dokumentwiederherstellung und unmittelbare Reaktion bei einem Manuskript mit 46-seitigem gesetztem PDF-Export. Windows-Tastaturbedienung sowie lesbare Android-Beschriftungen und erreichbare Schaltflächen wurden bestätigt. Die APK-Signaturprüfung war laut Betreiber erfolgreich; Windows-Installer sind derzeit nicht codesigniert.


## Änderungen im Kandidaten

- Vereinheitlichtes Fließtext-/Rahmenlayout, bearbeitbare Text- und Grafikrahmen,
  verketteter Textfluss, Seitenstile, laufende Kopfzeilen und Grafikpositionierung.
- Drehung und Schreibrichtung von Tabellenzelltext sowie weitere Tabellenwerkzeuge.
- Sichtbarer Validierungsfortschritt, tatsächliche Prüfanzahl und Einzelzeiten;
  lange Validierungen geben die Ereignisschleife für Oberflächenaktualisierungen frei.
- PDF-Fußnoten und Publikationstreue, Medien-/Paketerhaltung,
  verbindungsgebundene OJS/OMP/WebDAV-Zieladressen und OIDC/JWKS-Härtung.
- Explizite RC-Freigabe mit Wiederverwendung der genehmigten Build-Dateien;
  keine automatische Umwandlung in das allgemeine stabile „latest“-Update.

Das portable Format bleibt **OMI-SPEC-320@0.3.0**. Die Anwendungsversion 1.0
ändert keine Draft-Reifegrade und bestätigt keine unabhängige Konformität.

| Ziel | RC-Quellidentität / Umfang |
| --- | --- |
| Web | **RC `1.0.0-rc.1`**, gehostete Browserversion |
| Android 10+ | **RC `1.0.0-rc.1`**, direktes APK-Paket; Google Play ist ein getrennter Kanal |
| Windows 11 | RC-Quellstand/Build vorhanden; Desktop-Abnahme und Codesignierung ausstehend; öffentlicher Installer `0.3.0-beta.13` |
| Windows MSI | `1.0.0.1` |
| Android eingecheckter versionCode | `1353`; Play-Release-Workflow erzeugt einen höheren laufabhängigen Code |
| Ubuntu 22.04/24.04 x86-64 | **Linux Preview für RC1**; Linux-CI und manueller `linux-device`-Nachweis bleiben erforderlich |
| macOS Intel / Apple Silicon | **Preview**; keine unbelegte Signierungs-/Notarisierungszusage |
| iOS/iPadOS | **Experimentell**; Kurzversion `1.0.0`, Build `26`; kein öffentlicher App-Store-/TestFlight-Release zugesagt |
| OJS / OMP | OJS 3.5.0-4/5 sind Route-A-Ziele; OMP bleibt **Preview** |

Linux nativ erbt Rust `glib 0.18.5` über Tauri GTK3/WebKit.
[#271](https://github.com/open-manuscript-initiative/open-manuscript-studio/issues/271)
und die Warnung bleiben offen. Preview repariert die Abhängigkeit nicht.
Der Merge von #850 genehmigte den Supportumfang; Überprüfungsziel ist
**11. November 2026**. Browserbetrieb unter Linux lädt diese native GTK-Kette nicht.

## Desktop-Veröffentlichung und stabiles 1.0

Die Verfügbarkeit des Web-/Android-RC genehmigt weder alle Desktop-Ziele noch das spätere stabile `v1.0.0`. Der vollständige Veröffentlichungsnachweis ist weiterhin unvollständig. Offen sind unter anderem native Linux-Tests, Windows-Codesignierung, die gemeinsame Wiederherstellung von Anwendung und kompatiblem Datenzustand sowie verbleibende Host-/Integrationsnachweise. Erfolgreiche Funktionsbeobachtungen bleiben im Betreiberbericht erhalten.

Für die weitere Veröffentlichung gilt das [finale Abnahmeverfahren](https://github.com/open-manuscript-initiative/open-manuscript-studio/blob/e1200268ad549c0a40ace8724715cd2405e9d03c/docs/release/2026-11-04-rc1-final-acceptance.md). Das stabile `v1.0.0` erfordert eine spätere Entscheidung nach der RC-Beobachtung.
